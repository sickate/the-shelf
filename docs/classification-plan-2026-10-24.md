## 2. 分类体系：《中国图书馆分类法》（中图法，第五版）

**推荐中图法**，理由：
- 国内图书馆与出版 CIP 数据的通用标准，中文书版权页“中图分类号”直接可得，可核验、不是自创体系。
- 严格分级：22 个基本大类（A–Z）→ 二级 → 三级…，例如 `T 工业技术 › TP 自动化技术、计算机技术 › TP3 计算技术、计算机技术 › TP31 计算机软件 › TP311 程序设计、软件工程 › TP311.1 程序设计`。
- 外文书也能归入同一体系（由 AI 依内容判定）。

备选：杜威十进分类法 DDC（英文世界通用，但表本身受版权许可约束、中文书无现成号）、自定义标签树（灵活但不科学、不可核验）。不推荐。

**显示层级**：存储完整分类号（如 `TP311.1`），界面按前缀生成树。因本库计算机书占绝大多数，书架侧栏采用“自适应树”：只含一个子类的层级自动合并（例如 `T › TP` 合并显示为“计算机技术”），每个节点显示册数，默认展开到有意义的分叉层级。

## 3. 分类表数据

- 新增 `app/clc.json`：分类号 → 类名的节点表。完整中图法有数万条且为出版物，**不整表录入**；收录 22 个大类 + 全部二级类 + 本库实际用到的子树到 3–5 级（预计 300–600 条，重点 TP、O、N、B、F、I、Q、R、H）。
- 生成方式：AI 起草 + DeepSeek 检索图书馆/国图公开类目页面核对类名；主 Agent 抽查。表随代码版本化，后续可增补节点。
- 校验：任何写入的分类号必须能在表中找到自身或最长前缀；找不到的号截到最长已知前缀，并记录原始号。

## 4. 自动归类流程（每本书）

1. **检索候选号**：DeepSeek Search `<书名> 中图分类号`（`count: 8`），从结果摘要中用正则抽取形如 `TP311.1` 的分类号及来源站点（图书馆目录、出版社、书店页面），作为候选。
2. **AI 判定**：调用 oai 网关（gpt-luna medium，json_object），输入：书名、现有文件夹分类、AI 详情（summary/tags/keyPoints，若已生成）、候选号及来源、该书所在子树的候选类目列表（从 `clc.json` 截取，限制选择范围）。输出：`{primary:"TP311.1", secondary:["TP393"], basis:"cip|inferred", reason, confidence}`。
3. **服务端校验**：分类号格式、存在于 `clc.json`（或截到最长前缀）；`basis:"cip"` 时必须在候选号里出现过（检索到的 CIP 号）；否则降级为 `inferred`。
4. **人工修正**：所有者可在详情页用分类选择器改正（`source:"manual"`），之后批量任务不再覆盖。

- 同步单飞与错误处理沿用 F4 的租约/不自动重试规则；批量脚本 `scripts/mvp-classify.mjs` 并发 1，可中断续跑。
- 成本：每本 1 次检索 + 1 次网关调用；约 445 本 ≈ $0.33 检索费（2026-11-01 起），网关约 1–1.5 小时。须在 AI 简介批量结束后运行（网关全局并发 1）。

## 5. 数据与接口

```sql
CREATE TABLE IF NOT EXISTS book_class (
  book_id TEXT PRIMARY KEY REFERENCES books(id),
  clc TEXT NOT NULL,            -- 主分类号，如 TP311.1
  secondary TEXT,               -- JSON 数组，副分类号
  source TEXT NOT NULL CHECK (source IN ('cip','ai','manual')),
  confidence TEXT, reason TEXT, evidence_url TEXT, raw_code TEXT,
  status TEXT NOT NULL CHECK (status IN ('generating','ready','failed')),
  lease_until TEXT, updated_at TEXT NOT NULL);
CREATE INDEX IF NOT EXISTS book_class_clc ON book_class (clc);
```

- `GET /api/books`：每本增加 `clc`（分类号）；`categories` 保留。
- `GET /api/clc`：返回 `clc.json` 中本库用到的节点及其祖先（带册数），供侧栏树与选择器使用；可缓存。
- `POST /api/books/:id/class[?force=1]`（所有者）：自动归类；`PUT /api/books/:id/class`（所有者）`{clc}` 手动指定。
- 原 `books.category` 不删除，界面改称“来源目录”，作为归类输入之一。

## 6. 界面

- 书架侧栏：中图法分类树（可展开/折叠，节点册数，选中节点 = 前缀过滤，URL 参数 `clc=TP31`）；“未分类”节点列出尚未归类的书。原文件夹分类移到“更多筛选”。
- 书卡：显示末级类名；详情页：完整分类路径面包屑（每级可点回书架过滤）+ 分类号 + 依据（CIP / AI 推断 / 手动）+ 所有者“修改分类”。
- 与现有过滤（格式、大小等）组合，计数随过滤联动。

## 10. `app/clc.json` 格式（C1/C2 共同契约）

```json
{"edition":"中图法第五版（本库子集）","nodes":[{"code":"T","name":"工业技术","parent":null},{"code":"TP","name":"自动化技术、计算机技术","parent":"T"},{"code":"TP3","name":"计算技术、计算机技术","parent":"TP"}]}
```
- `code` 唯一；`parent` 必须是表内已有的 code（根为 null）；数组按先父后子排序。
- 复分号（如 `TP3-0`、`TP311.1`）也作为普通节点，显式给出 parent。
- 归类结果可以落在任意表内节点（不要求叶子）；表外号截到最长“表内前缀”（逐字符去尾，含去掉 `.` 和 `-` 后缀）。

## 11. 资料类型：图书与非书资料分开（2026-10-25 用户追加）

用户要求：不是书的资料单独分类，例如课程介绍、论文、论坛文章汇总。

- 每条归类结果新增 `doc_type`，取值与显示名：

| doc_type | 显示名 | 包括 |
| --- | --- | --- |
| `book` | 图书 | 正式出版或成书的图书、电子书、开源书 |
| `course` | 课程资料 | 课件、讲义、作业/答案、考试、课程介绍与大纲、实验指导 |
| `paper` | 论文与报告 | 学术论文、学位论文、技术报告、白皮书、研究报告 |
| `articles` | 文章汇编 | 论坛/博客/公众号文章合集、专栏整理、电子期刊、新闻汇总 |
| `manual` | 手册与文档 | 产品手册、官方文档、用户指南、规范标准、配置说明 |
| `other` | 其他资料 | 表格、单页、清单、无法判断的零散资料 |

- 判定：与中图法归类在同一次 AI 调用中给出（输入已有书名、来源目录、AI 简介、检索候选、格式与大小）；服务端校验枚举，非法值视为 `other`。CIP 号命中通常意味着 `book`。
- 非书资料仍保留主题分类号（详情页显示“主题：…”），但**不进入书架侧栏的中图法“图书”树**。
- 接口：`GET /api/books` 每本增加 `docType`（null = 未归类）；`GET /api/books/:id` 增加 `docType`；`GET /api/clc` 的 `nodes[].count` 只统计 `docType` 为 `book` 或 null 的条目，另返回 `docTypes: {course: n, paper: n, …}`；`PUT /api/books/:id/class` 接受可选 `docType`（手动修改）。
- 界面：侧栏分两段——“图书”（中图法树）与“非书资料”（按类型列出，带册数，URL 参数 `type=course`）；书卡与详情页显示资料类型标签；所有者在“修改分类”中可改资料类型。
- 迁移 `0004_doc_type.sql`：`ALTER TABLE book_class ADD COLUMN doc_type TEXT`。已归类的 11 本在批量重跑（`--force`，跳过手动）时补齐。
