# The Shelf 开发计划

第一版交付可在本机运行、可构建为 GitHub Pages 静态网站的真实收藏书架，同时提供个人登录、私人文件读取与按需 AI 任务的业务后端。云端凭证缺失时明确显示未配置，不伪造上传状态或 AI 回答。

更新日期：2026 年 10 月 14 日。阶段：首版已实现并完成本地集成验证。

## 技术与边界

静态网站采用 Astro 和 TypeScript，后端采用 Node.js 内置 HTTP 与 SQLite，导入使用 Python 标准库。无需购买数据库、服务器或额外模型额度。运行需要 Node.js 24 及以上、Python 3.9 及以上；本机 PDF 文本准备可使用 pdftotext，MOBI 转换需可选的 Calibre。

代码与公开目录可以进入仓库，私人文件映射、SQLite、提取正文、密钥与会话必须留在被忽略的本机状态目录。应用不修改收藏源文件。

## 页面设计

书架使用暖白背景、墨色正文和少量朱红强调色。左侧分类导航，主区提供搜索、格式与可用性筛选、紧凑书籍网格和分页。封面默认由书名、分类和颜色排版生成，避免导入未经确认授权的图片。移动端把侧栏收起为选择器。

详情页提供面包屑、书名与作者、分类和格式标签、完整文件列表、私人阅读入口、书内提问、章节与全书总结、作者资料以及已发布结果。每个格式单独显示大小和状态；未上传不显示可下载。页面会根据后端登录与能力状态展示可执行的操作。

公开文档区有目录侧栏、可直接读取的正文、原文与合并原文链接。所有页面支持实际站点基路径，无 JavaScript 时详情和文档正文仍可读。

## 工作拆分

| 工作 | 模型 | 所有文件 |
| --- | --- | --- |
| 导入、公开目录和文档导出 | 6.0 Luna medium | scripts/import-books.py、scripts/export-docs.mjs、导入与导出测试 |
| 登录、私人文件、R2 与 AI 任务 | 6.1 Sol medium | server 目录与后端测试 |
| 书架、详情、阅读器与文档界面 | 6.1 Sol medium | src 目录 |
| 契约、项目配置、集成与验证 | 主代理 | 配置、部署说明、开发计划与集成检查 |

三个子任务先阅读数据与接口契约，按各自拥有的目录编辑，共享输出在集成阶段验证。子代理不签发密钥、不上传书籍、不操作现有生产服务、不自行购买或部署新服务。

## 开发顺序

1. 完成数据与接口契约，配置依赖、忽略规则和命令。
2. 并行实现导入与公开数据、业务后端、静态网页。
3. 用已有收藏快照生成真实目录；大文件和异常文件只登记。
4. 构建公开文档与全部书籍详情页，连接后端登录、任务与阅读器。
5. 验证门槛边界、权限隔离、文件 Range、任务去重、预算控制和静态产物隐私。
6. 运行本地预览，检查桌面与移动布局，修正实际问题。
7. 提供 GitHub Pages 工作流和后端运行说明；有凭证时再接入 R2 与现有 AI。

## 完成标准

真实收藏可以搜索、分类、分页并查看各格式详情。20 MB 以上只登记，零字节文件不可阅读。public 与 dist 中没有本机路径、源电子书、正文、私人历史或密钥。匿名访问者可读所有公开文档及机器索引。

后端登录保护私人文件与 AI；未知来源写操作被拒绝。任务先持久保存，刷新不重建相同在途任务，工作进程有并发和调用上限，失败不会无限重试。没有正文时返回明确状态，不生成未经依据的书内回答。

PDF 和 EPUB 阅读器支持授权文件；MOBI 和 AZW3 提供原格式下载及需要转换的提示。现有 AI 服务没有书籍流式接口，第一版展示排队和完成状态。

## 部署前的配置

部署需要实际 GitHub 仓库、站点基路径、业务后端地址与单用户登录密码。云端文件接入需要 R2 配置及剩余额度；AI 接入需要现有任务服务接受的专用 Key。这些配置不影响本地目录、公开文档与后端逻辑的开发和验证。
